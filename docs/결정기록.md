## D-16 킬스위치 차단 범위

- 날짜: 2026-11-03
- 출처: 사용자 결정(DBG-pm 전달, 승인 카드 `20261103-0050-DBG-pm-killswitch-scope`)
- 결정:
  - 막는 지점: `HandlerInterceptor` 한 곳에서 세션 시작과 배틀·야추·RPS의 match·create·join을 막는다.
  - 진행 중 판: 시작만 차단한다. 진행 중 세션의 기록 제출은 허용하고, 방은 끝까지 진행한다.
  - 응답: 503 + `GAME_DISABLED`. 프론트는 상태 코드가 아니라 코드값으로 구분한다.
  - 어드민 예외 없음: 어드민도 끈 게임을 시작할 수 없다. 추천안과 다른 사용자 선택이다. 프론트의 어드민 통과 동작은 이 결정에 맞춰 바꾼다(T-33).
  - (2026-11-03 위임 결정, D-17: 매칭 계열은 인터셉터가 아니라 서비스의 `ALREADY_IN_ROOM` 판단 뒤에서 차단한다. 재접속을 보호하기 위해서다. `session/start`는 인터셉터를 유지한다. 재대결과 WAITING 상태 야추의 시작도 차단한다.)
- 근거:
  - 막는 지점: 서비스별 검사는 수정 파일이 많고 랭킹 작업과 겹친다.
  - 진행 중 판: 제출까지 막으면 기록이 사라지고, 방 강제 종료는 WebSocket 작업이 크다.
  - 응답: 야추·RPS 매칭의 락 실패와 배틀 컨트롤러의 처리 실패가 이미 503 + `MATCH_UNAVAILABLE`을 쓴다(2026-11-03 코드 확인). 그래서 상태 코드만으로는 구분되지 않는다.
  - 어드민 예외 없음: 전달받은 내용에 없음
- 대안: 서비스별 검사, 제출까지 차단, 방 강제 종료, 403 응답. 어드민 쪽 추천안의 내용은 전달받은 내용에 없음
- 감수한 위험: 악용 때문에 게임을 꺼도 이미 받은 세션으로 기록을 넣을 수 있다.
- 관련 ID: D-17, T-23, T-33, T-34
