# 안정화 사용자 문구 대조

- 작성: 2026-11-03 (DBG-design)
- 대상: main `a5347ab`(비교 기준 `4183a49`), 미커밋 worktree `DBG-frontend3`(스도쿠, 기준 `7f4f874`), `DBG-frontend2`(T-33, 기준 `a5347ab`)
- 방법: 코드와 `docs/design/` 대조. 브라우저로 띄우지 않았고, 표시 경로는 코드를 읽어 확인했다.
- 미커밋 worktree의 행 번호는 작성 시점 값이다. DBG-frontend2는 대조 중에도 수정이 이어져 일부 파일의 행이 밀렸고, 인용은 마지막 확인 값이다.
- 기존 정의서는 고치지 않았다. 바꿀 내용은 맨 아래 "개정 제안"에 있다.

## 요약

- **단일 화면정의서는 없다.** `docs/design/`의 게임별 문서를 정의서로 보고 대조했다.
- **스도쿠 정의서, 킬스위치 안내 정의서, 어드민 화면 정의서가 없다.** 그래서 새 문구 대부분이 "정의서에 없음"이다.
- 어긋남은 상 3건, 중 5건, 하 4건이다. 표 밖의 참고 1건(스도쿠 룰 문구)은 따로 적었다.
- 상 3건은 모두 이번에 새로 쓴 문구 자체가 아니라, 안정화에서 건드린 오류 경로에 남은 문제다. 내부 코드 노출과 안내 뒤 화면이 멈추는 경우다.
- 일반 모드와 Excel 모드는 같은 문구를 쓴다. 모드별 차이는 S-05 한 건이다.

## 7. 개정 제안 (기존 정의서는 수정하지 않음)

1. **스도쿠 정의서 신설** (`docs/design/sudoku.md`): 판 상태(`checking`, `ended` 포함)별 표시와 1절 문구를 일반·Excel 양쪽으로 적는다. 룰 문구의 힌트 동작도 바로잡는다.
2. **공통 오류 문구 정의 신설**: 등록 실패, 코드별 오류, 킬스위치 안내 K-01을 한 곳에 둔다. "내부 코드를 화면에 표시하지 않는다"를 규칙으로 넣는다.
3. **용어 규칙**: 사용자 문구에서 "세션"은 로그인에만 쓰고, 게임 진행은 "판"으로 쓴다. 띄어쓰기는 "해 주세요"로 통일한다. `rsp-game.md:984`의 "다시 로그인해주세요"가 대상이다.
4. **어드민 화면 정의 신설**: 게임 관리 화면의 비활성화 문구를 D-16 기준으로 적는다.
